## Prerequisites

- Kubernetes 1.27+
- Helm 3.12+
- An ingress controller (nginx-ingress recommended)
- cert-manager (optional, for automatic TLS)

## Quick Start

Install with zero configuration - only domain names are required.
All passwords, keys, and credentials are auto-generated and preserved across upgrades.

```bash
helm install stackweaver ./deploy/helm/stackweaver \
  --namespace stackweaver --create-namespace \
  --set ingress.hosts.app=stackweaver.example.com \
  --set ingress.hosts.auth=auth.stackweaver.example.com
```

This deploys:
- **Core**: API, Frontend, Orchestrator, OpenTofu Runner, Ansible Runner
- **Dependencies**: PostgreSQL 17, Redis 8, Garage, Zitadel + Login UI
- **Networking**: Two-domain ingress with TLS
- **Secrets**: Auto-generated for PostgreSQL, Garage storage, encryption, and Zitadel

After install, follow the post-install notes (`helm get notes stackweaver -n stackweaver`) to complete the Zitadel initialization.

```
                    │     Ingress Controller    │
                    │  (nginx / traefik / etc)  │
                    └──────┬──────────┬─────────┘

            ┌──────────────┘          └──────────────┐

   │ /v1/modules  → "│                  │      (OIDC/gRPC)│
   │ /.well-known → "│                  │                 │
   │ /auth/*    → API│                  │                 │

```

## Ingress

The chart creates two Ingress resources for a **two-domain layout**:

| Domain | Service | Path |
|--------|---------|------|
| `ingress.hosts.app` | Frontend | `/*` (catch-all, includes `/login/*` for the custom login UI) |
| `ingress.hosts.app` | API | `/api/v2`, `/auth/*`, `/.well-known/terraform.json`, `/v1/modules`, `/health` |
| `ingress.hosts.auth` | Zitadel | `/*` (catch-all) |

**Why two domains?** Zitadel requires its own domain for OIDC (`ExternalDomain` setting). Combining Frontend + API on a single domain eliminates CORS issues since the API routes have a distinct `/api/v2` prefix.

### TLS with cert-manager

```yaml
ingress:
  annotations:
    cert-manager.io/cluster-issuer: letsencrypt-prod
  tls:
    enabled: true
    secretName: stackweaver-tls
    authSecretName: stackweaver-auth-tls
```

### Disable ingress

If you use a service mesh or external load balancer:

```yaml
ingress:
  enabled: false
```

## Secrets

The chart supports two modes for managing secrets.

### Auto-Generated (Default)

When `secrets.<component>.secretName` is empty (the default), the chart creates Kubernetes Secrets with cryptographically random values. These secrets:

- Are preserved across `helm upgrade` (uses Helm `lookup` to check for existing values)
- Are preserved on `helm uninstall` (annotated with `helm.sh/resource-policy: keep`)
- Use sensible key names (`password`, `access-key`, `secret-key`, `encryption-key`, `masterkey`, etc.)

The four auto-generated secrets:

| Secret Name | Keys | Description |
|---|---|---|
| `<release>-postgresql` | `password` | Random 24-character password |
| `<release>-storage` | `access-key`, `secret-key` | Garage-format key ID (`GK…`) + random 64-char secret |
| `<release>-encryption` | `encryption-key` | 64-character hex key |
| `<release>-zitadel` | `masterkey`, `admin-password`, plus 6 placeholder keys | 32-char masterkey, complex password |

### External Secrets (GitOps-Safe)

For production and GitOps workflows, provide pre-existing secrets:

```yaml
secrets:
  postgresql:
    secretName: my-postgresql-secret
  storage:
    secretName: my-storage-secret
  encryption:
    secretName: my-encryption-secret
  zitadel:
    secretName: my-zitadel-secret
```

When all four `secretName` values are set, the chart creates **zero** `kind: Secret` resources - all rendered manifests are safe for Git.

You can mix modes: auto-generate some secrets and bring your own for others.

### Secret Key Names

The expected key names inside each secret can be customised:

```yaml
secrets:
  postgresql:
    secretName: my-secret
    keys:
      password: my-custom-key-name
```

See the values table below for all available key overrides.

## Frontend Runtime Configuration

The frontend image is **generic** - no domain-specific build args are needed. The chart generates an `env.js` file at deploy time from the ingress host configuration.

| Variable | Source |
|---|---|
| `VITE_API_URL` | `https://<ingress.hosts.app>/api/v2` |
| `VITE_ZITADEL_REDIRECT_URI` | `https://<ingress.hosts.app>/auth/callback` |
| `VITE_ZITADEL_CLIENT_ID` | Injected from the Zitadel secret at pod startup |

The frontend reads `window.__STACKWEAVER__` from `env.js`, with fallback to Vite build-time `import.meta.env` variables for development.

## Bring Your Own Infrastructure

Disable bundled dependencies and provide external connection details:

```yaml
postgresql:
  enabled: false
  external:
    host: my-postgres.example.com
    port: 5432
    username: stackweaver
    database: stackweaver
    sslmode: require

redis:
  enabled: false
  external:
    host: my-redis.example.com
    port: 6379

garage:
  enabled: false

storage:
  endpoint: https://s3.amazonaws.com
  region: eu-west-1
  useSSL: true

zitadel:
  bundled: false
  external:
    issuer: https://auth.example.com
```

## Upgrading

```bash
helm upgrade stackweaver ./deploy/helm/stackweaver \
  --namespace stackweaver \
  -f my-values.yaml
```

Auto-generated secrets are preserved. Pods are automatically restarted when ConfigMaps change (via checksum annotations).

## Uninstalling

```bash
helm uninstall stackweaver --namespace stackweaver
```

**Note**: Auto-generated Secrets (`helm.sh/resource-policy: keep`) and PersistentVolumeClaims are not deleted automatically.
Remove them manually if no longer needed:

```bash
kubectl delete pvc -l app.kubernetes.io/instance=stackweaver -n stackweaver
kubectl delete secret -l app.kubernetes.io/managed-by=Helm -n stackweaver
```
